# IkuaiRouter-SDK 代码优化工作计划

## 执行原则

1. 每个阶段完成后进行编译验证，确保不引入新问题
2. 保持所有公开 API 的行为兼容性（除异常类型细化外）

4. 优先处理稳定性/可靠性问题，再处理性能和代码质量

## 阶段一：稳定性/可靠性修复 [高优先级]

### 1.1 OkHttpClient 实例复用 `已完成`

**问题**: 每次 `executeAction` 和 `login` 都创建新的 OkHttpClient 实例，导致连接泄漏、线程暴涨、TIME_WAIT 堆积。

**方案**:
- `RouterAgent` 中将 `OkHttpClient` 改为实例变量，构造时创建一次
- 每个 `RouterAgent` 实例持有独立的 `OkHttpClient`（不同节点不会混用）
- `TrustAllCertOkHttpClient` 改为构建方法，仅在 `RouterAgent` 构造时调用一次

**涉及文件**:
- `RouterAgent.java` — 新增 `OkHttpClient` 实例字段，构造函数中初始化
- `TrustAllCertOkHttpClient.java` — 方法签名不变，仅调用时机改变

**验证**: 编译通过 + 单元测试通过

---

### 1.2 Response 资源正确关闭 `已完成`

**问题**: `login()` 中 Response 未关闭；`executeAction()` 中若 `body().string()` 抛异常则 `close()` 不会执行。

**方案**:
- `login()` 方法改用 `try-with-resources` 包裹 Response
- `executeAction()` 方法改用 `try-with-resources` 包裹 Response
- 在 try 块内完成所有 body 读取和解析工作

**涉及文件**:
- `RouterAgent.java` — `login()` 方法、`executeAction()` 方法

**验证**: 编译通过 + 确认 Response 在所有路径上被关闭

---

### 1.3 NPE 防护 — response.body() 空检查 `已完成`

**问题**: OkHttp 中 `response.body()` 可返回 null，当前代码未做空判断。

**方案**:
- 在 `login()` 和 `executeAction()` 中，`response.body()` 取出后进行 null 判断
- 为 null 时抛出明确的异常（待 1.4 异常分层完成后使用 `IkuaiRouterNetworkException`，初期先用 `IkuaiRouterException`）

**涉及文件**:
- `RouterAgent.java`

**验证**: 编译通过

---

### 1.4 SSL 初始化异常处理 `已完成`

**问题**: `TrustAllCertOkHttpClient` 中 SSL 初始化失败被 `e.printStackTrace()` 吞没，后续 NPE 无法定位根因。

**方案**:
- 移除 try-catch 中的 `e.printStackTrace()`
- 改为 `throw new RuntimeException("SSL context initialization failed", e)` 快速失败
- 异常将通过 `RouterAgent` 构造函数向上传递给调用方

**涉及文件**:
- `TrustAllCertOkHttpClient.java`

**验证**: 编译通过

---

### 1.5 线程安全 — CookieStore `已完成`

**问题**: `HashMap<String, List<Cookie>>` 非线程安全，多线程下会导致并发修改异常。

**方案**:
- `RouterAgent` 中 `cookieStore` 类型从 `HashMap` 改为 `ConcurrentHashMap`
- 所有构造函数中对应修改
- `TrustAllCertOkHttpClient` 方法参数类型改为 `Map<String, List<Cookie>>`（接口兼容）

**涉及文件**:
- `RouterAgent.java` — 字段声明、所有构造函数
- `TrustAllCertOkHttpClient.java` — 参数类型调整
- `IkuaiRouter.java` — `getCookieStore()` 返回类型调整

**验证**: 编译通过

## 阶段三：性能优化 [中优先级]

### 3.1 端口查找算法优化 `已完成`

**问题**: O(P×N) 复杂度，大规模配置下性能差。

**方案**:
- 新增私有方法 `parseUsedPorts(List<NetMapping>, List<String> interfaces) → Set<Integer>`
- 新增私有方法 `parseWanPortInto(Set<Integer>, String wanPortSpec)`
- 重写 `findAvailableNetMappingWanPort` 和 `findAvailableNetMappingWanPortMultiInterface`：先调用 `parseUsedPorts` 构建已占用端口集合，再线性遍历候选端口用 `contains()` 判断
- 重写 `isWanPortInUse` 和 `isWanPortInUseMultiInterface`：复用 `parseUsedPorts`

**业务逻辑保持**:
- 接口匹配规则不变：映射条目的接口列表与目标接口有交集即视为匹配
- 端口格式解析不变：支持单端口、范围、逗号组合

**涉及文件**:
- `IkuaiRouter.java` — 新增 2 个私有方法，重写 4 个公开方法

**验证**: 编译通过 + 与原有逻辑行为一致（可用测试用例验证）

---

### 3.2 IP 查找算法优化 `已完成`

**问题**: 四层嵌套循环 × 线性扫描列表，O(IP数 × 列表长度)。

**方案**:
- 在 `findAvailableIpAddr` 方法开头，将 DHCPHost 和 DHCPStatic 列表中的 IP 预先放入 `HashSet<String>`
- 内层循环改为 `usedIps.contains(current_ip)` 判断，O(1) 复杂度
- 保持四层嵌套的 IP 遍历逻辑不变（仅替换内层查找方式）

**涉及文件**:
- `IkuaiRouter.java` — `findAvailableIpAddr` 方法

**验证**: 编译通过 + 与原有逻辑行为一致

## 阶段四：代码质量优化 [中优先级]

### 4.1 重复代码抽取

**问题**: 端口检测存在 4 处几乎相同的端口解析逻辑（split逗号、split横杠、判断单端口/范围），每块约 30 行。

**方案**:

- 确认不再有独立的端口解析逻辑散落在各方法中
- 注：此项与 3.1 合并完成（3.1 优化算法时已完成抽取）

**涉及文件**:
- `IkuaiRouter.java`

**验证**: 编译通过 + 端口解析逻辑仅存在于公共方法中

---

### 4.2 JSON 反序列化统一封装

**方案**:
- 在 `IkuaiRouter` 中新增私有泛型方法：

```java
private <T> T parseData(ResponseShow response, String dataKey, TypeReference<T> type) throws IkuaiRouterException {
    JsonNode dataNode = objectMapper.readTree(response.getData());
    JsonNode targetNode = dataNode.get(dataKey);
    if (targetNode == null) {
        throw new IkuaiRouterException("Response missing expected key: " + dataKey);
    }
    return objectMapper.readValue(targetNode.toString(), type);
}
```

- 将所有 15+ 处重复的 getData → readTree → get → readValue 模式替换为调用该方法

**涉及文件**:
- `IkuaiRouter.java` — 新增 1 个私有方法，修改所有 getter 方法体

**验证**: 编译通过 + 所有 getter 方法行为一致

---

### 4.3 批量操作结果收集

**问题**: `downNetMappingByLanIp`、`delNetMappingByIpAddr` 等批量操作中间失败时前面已执行的不回滚。

**方案**:
- 循环内部 try-catch，记录每条规则的操作结果
- 返回结果改为包含每条规则执行状态的列表，供调用方判断部分成功/部分失败
- 不再中途抛异常中断，而是收集全部结果后统一返回

**涉及文件**:
- `IkuaiRouter.java` — `downNetMappingByLanIp`、`delNetMappingByIpAddr` 等批量方法

**验证**: 编译通过 + 批量操作中单条失败不影响后续条目执行

## 阶段五：安全与命名 [低优先级]

- `IkuaiRouter` 暴露 `destroy()` 方法供上层调用

**涉及文件**:
- `RouterAgent.java`
- `IkuaiRouter.java`
